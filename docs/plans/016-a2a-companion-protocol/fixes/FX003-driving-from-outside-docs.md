# Fix FX003: Document `--wait` / `--after` as the canonical operator pattern

**Created**: 2026-05-01
**Status**: Proposed
**Plan**: [Companion Experience](../companion-experience-plan.md)
**Source**: Live demo F1 — `--wait` / `--after` exist on `inside inbox list` but are absent from every operator-facing doc; canonical guides teach `sleep N && cat`
**Domain(s)**: docs only

---

## Problem

`npx minih inside inbox list --wait <ms> --after <id>` is the **correct** way to block on the agent's reply from outside. It's the operator's analogue to the agent's `wait_for_any`. But:

- `docs/how/companion-mode.md` shows `sleep 5` + `cat`.
- `agents/coordination-smoke-test/outside.md` doesn't mention `--wait`.
- `agents/code-review-companion` outside script doesn't mention `--wait`.
- `AGENTS_README.md` has no operator round-trip cheat-sheet.
- The auto-generated `init-coordinated` scaffolding produces an `outside.md` without it.

A third-party agent author who reads our docs will write polling-with-sleep — same bug, every time. This is a **paved-cowpath gap**: the right tool exists; the doc surface drives users to the wrong tool.

## Proposed Fix

1. Replace every `sleep N && cat` near a coordination round-trip with `--wait` / `--after` patterns.
2. Add a single canonical "Driving an agent from outside" how-to page that pairs each `outside ... send` with its matching `inside ... list --wait`.
3. Update `AGENTS_README.md` with a one-paragraph cheat-sheet linking to the new page.
4. Make sure the existing `outside.md` files in `agents/` are updated to use the canonical pattern.
5. Update the scaffolding template in `init.ts` so newly-scaffolded coordinated agents inherit the right pattern.
