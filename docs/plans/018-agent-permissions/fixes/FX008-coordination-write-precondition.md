# FX008 — Boot precondition for coordination + `write: deny` mismatch

**Created**: 2026-05-04
**Status**: PROPOSED (post-R6 — implements today, ships behind FX008 dossier review)
**Plan**: 018-agent-permissions
**Source**: GitHub issue [#25](https://github.com/AI-Substrate/minih/issues/25) ("Companion farewell envelope blocked by default `restricted` permission preset (`write: deny`)") — converged with Chainglass agent 2026-05-04.
**Domain(s)**: runner (compile + boot guard), cli (run command flag, error allocation), agents (canonical companion frontmatter)
**Validation references**: workshop 002 § Q1 — `docs/plans/018-agent-permissions/workshops/002-permission-error-protocol.md` (5-signal protocol)

## Problem

`minih run <coord-enabled-agent>` silently boots into a structurally-doomed run when the resolved permission policy denies `write`. The coordinated-agent contract (workshop 002 § Q1, `docs/how/companion-mode.md`) requires writing `output/report.json` on `control:stop` or idle-budget exit; under any preset with `write: deny` the run executes for up to `timeout` seconds (7200 s default for `code-review-companion`) and exits cleanly without ever producing the canonical envelope. Orchestrators consuming `runs/*/output/report.json` see absent files; the only forensic trail is a `progress`-typed inbox message generated by the agent itself when it tries to write — by which point ~14+ minutes of work and budget are wasted (Chainglass repro: 14m 27s briefing-sent → manual-pid-diagnosis on `runs/2026-05-04T16-16-02-885Z-9355`).

Two compounding bugs make this reachable:

1. **Stale local installs of `code-review-companion` carry no `permissions` block at all.** The canonical at `agents/code-review-companion/prompt.md` declares `preset: read-only` with `shell: allow + network: allow` overrides, but installs that pre-date that frontmatter (e.g. Chainglass install timestamped `2026-05-03T06:02:52Z`) have no `permissions:` block. The resolver falls through to release-default `restricted` (post-R6) → all-deny → write blocked.
2. **Even with the canonical frontmatter honored, `read-only`/`restricted` set `write: deny`** and the canonical's overrides bridge `shell` + `network` but not `write`. So the documented contract is structurally impossible under the agent's own declared policy.

## Proposed Fix

Two-track resolution. Both ship together under FX008 — they share the dossier because they target the same surface area (the canonical companion + the boot path that runs it):

**Track A — canonical companion `write: allow` override (FX008-1).** One-line addition to `agents/code-review-companion/prompt.md` frontmatter `permissions.overrides`. Forward-going default for fresh installs and upgrades.

**Track B — runner boot precondition (FX008-2 .. FX008-5).** After `compile()` resolves the policy in `runAgent` (`src/runner/runner.ts:643-667`), assert: `!(definition.coordination?.enabled === true && resolvedPolicy.decisions.write === 'deny')` unless the operator passed `--allow-coord-write-deny`. Failure refuses to start the SDK session and fires the existing 5-signal denial protocol (`src/runner/permissions/error-signal.ts:188`) with new error code `E205 COORDINATION_WRITE_DENIED`. Operators see an actionable message naming the slug, the resolved preset, the provenance source (frontmatter / sidecar / env / release-default), and three remediation paths — all within seconds of `minih run`, before any tokens are spent.

The 5-signal protocol guarantees the failure is visible across all canonical surfaces: events.ndjson, run.json (`terminalReason: 'permission-coord-write-deny'`), inside-state (`status: 'error'` + `permissionError`), inside-inbox (`type: 'permission-error'` message readable via `minih outside inbox list`), exit code 126. Existing orchestrator polling on `verdict` or inbox `permission-error` types catches the failure with no contract change.

## Scope

### Track A — canonical companion frontmatter

`agents/code-review-companion/prompt.md` frontmatter:

```yaml
permissions:
  preset: read-only
  overrides:
    shell: allow
    network: allow
    write: allow         # NEW — required to write output/report.json (companion-mode contract)
```

`write: allow` is global within the run folder; `output/` narrowing is FX010 (deferred). For now we trade scope-precision for unblocking the documented contract. The companion's only legitimate write target IS `$MINIH_OUTPUT_PATH`, so the practical security delta is small.

### Track B — runner boot precondition

**Trigger condition**:

```ts
const writeDenied = resolvedPolicy.decisions.write === 'deny';
const coordEnabled = definition.coordination?.enabled === true;
const operatorOptedOut = !!config.permissionsOverride?.allowCoordWriteDeny;

if (coordEnabled && writeDenied && !operatorOptedOut) {
  throw new MinihError(
    'E205',
    formatCoordWriteDeniedMessage({ slug, presetName, source, ... })
  );
}
```

**Insert location**: `src/runner/runner.ts` immediately after the `await updateManifest(runDir, { permissions: ... })` call (lines ~643–673 — call opens at 657 with `compile()` upstream at 643; verify exact range against current file at implementation time) — _after_ the policy is stamped into `run.json` (so post-mortem inspection of the failed run shows the exact resolved policy that was rejected) but _before_ any SDK adapter session is opened.

**Error message** (locked):

```
E205 COORDINATION_WRITE_DENIED — Coordinated agent '<slug>' resolved to preset
'<presetName>' which denies write. Coordinated agents MUST write
output/report.json on exit (workshop 002 § Q1, docs/how/companion-mode.md).

Resolved from: <source>          # frontmatter | sidecar.lockedDefault | env | release-default

Remediations (pick one):
  1. Add `write: allow` to the agent's frontmatter `permissions.overrides`.
     Edit:  <agentDir>/prompt.md
  2. Pick a preset that allows write at the same source layer:
     `trusted` (allows shell+write+url) or `yolo` (allows everything).
  3. Pass --allow-coord-write-deny when running the agent (operator
     acknowledges the run cannot persist its envelope; you must be sure).

If the resolved source is 'sidecar.lockedDefault' you may need:
  minih agent permissions reset <slug>      # FX001 — clears the sticky lockedDefault
```

**`Resolved from:` provenance source** — IMPORTANT: `compile()` currently destructures away the `source` field from `resolvePreset()` (`compile.ts:59`: `const { presetName } = resolvePreset(sources)`). The preset source label is NOT exposed by `ResolvedPolicy`. The implementer has two options: (a) extend `ResolvedPolicy` with a `presetSource: 'frontmatter' | 'sidecar' | 'env' | 'release-default'` field and propagate it from `compile()` (preferred — single source of truth); OR (b) `assertCoordWriteAllowed()` calls `resolvePreset(sources)` directly to obtain the source label without going through `compile()`. The dossier specifies option (a) as the canonical fix; FX008-2 must include the type extension.

### CLI flag — `--allow-coord-write-deny`

Add to `minih run` command (`src/cli/commands/run.ts`). Boolean, default `false`, no env-var equivalent (intentional — must be explicit per invocation, never silently inherited from shell config). Wires through to `RunConfig.permissionsOverride.allowCoordWriteDeny`.

```bash
minih run code-review-companion --allow-coord-write-deny
```

Documented in `docs/how/permissions.md` § Coordinated agents with the warning: "You almost certainly don't want this. The coordinated-agent contract requires writing the farewell envelope; opting out means the canonical session record is unrecoverable."

Update the `output.ts` comment header to reference E205 in the Plan 018 enumeration block. Exit code 126 (`POSIX permission-denied`) — same as existing 5-signal protocol per `error-signal.ts:202`.

## Acceptance

- **AC-FX8.1** (Track A): `agents/code-review-companion/prompt.md` frontmatter has `permissions.overrides.write: allow`; companion run on a fresh `minih agent install code-review-companion` produces `output/report.json` on idle-budget exit. Demonstrated in `test/agents/companion-output-envelope.test.ts` (synthesises the file is written; does NOT spin up a real SDK session).
- **AC-FX8.2** (boot precondition): for ANY coordinated agent (`coordination: enabled`) where `compile()` resolves to a policy with `decisions.write === 'deny'`, `runAgent` refuses to start. Demonstrated by FX008-6 case (a).
- **AC-FX8.3** (5-signal coverage): the precondition denial fires events.ndjson, run.json `terminalReason`, inside-state `status: 'error'` + `permissionError`, inside-inbox `type: 'permission-error'` message, and exit code 126. Demonstrated by FX008-6 case (a) assertions across all five files.
- **AC-FX8.4** (error message): the formatted E205 message contains slug, presetName, presetSource (frontmatter / sidecar.lockedDefault / env / release-default), all three remediation options, and a hint about `permissions reset` when source is `sidecar.lockedDefault`. Demonstrated by string assertions in FX008-2 unit tests.
- **AC-FX8.5** (opt-out works): `minih run <slug> --allow-coord-write-deny` boots normally even when policy denies write. Demonstrated by FX008-6 case (b). Help text warns operators.
- **AC-FX8.6** (non-coord exempt): coordination-disabled agents with `write: deny` boot normally — the precondition only fires for `coordination: enabled` (workshop 001 § Q5 — yolo agents must keep working unchanged). Demonstrated by FX008-6 case (c).
- **AC-FX8.7** (additive enum — concrete assertion): every `switch`-on-`PermissionDeniedKind` site in the codebase compiles after the type widening AND has a default branch (or explicit `'coord-write-deny'` arm). Verified by: (a) `npm run build` green; (b) the dedicated regression test `test/runner/permissions/handler-kind-extension.test.ts` enumerating each switch site (use grep for `kind:` patterns in `src/runner/permissions/`, `src/adapter/`, and `src/runner/runner.ts`) and asserting each handler does not throw when given `kind: 'coord-write-deny'`; (c) FX008-3 task description lists the affected files explicitly so the implementer doesn't miss one.
- **AC-FX8.8** (no env-var fallback for opt-out): `MINIH_ALLOW_COORD_WRITE_DENY=1 minih run <slug>` does NOT bypass the precondition. Per-run flag only.
- **AC-FX8.9** (stderr opt-out banner): `minih run <slug> --allow-coord-write-deny` emits a stderr line matching regex `^\[minih\] Warning: --allow-coord-write-deny set; canonical session record will not be persisted` on every successful run. Demonstrated by FX008-6 case (b) stderr assertion.
- **AC-FX8.10** (env-var kill-switch): when `MINIH_DISABLE_COORD_WRITE_PRECONDITION=1` is set, the precondition does NOT fire regardless of coord+write-deny combination; a stderr warning is emitted on every bypass. This is the ops emergency rollback path. Demonstrated by FX008-8 unit tests.

## Out of scope

- **`$MINIH_OUTPUT_PATH` auto-narrowing** (suggested fix #1 in issue #25). FX010 territory — different design conversation about preset semantics + fs-guard allowedRoots injection. FX008 is strictly the boot guardrail; FX010 makes the canonical-flow ergonomic.
- **Pack-drift detection** (`agent install` upgrade semantics). Filed as GitHub issue [#26](https://github.com/AI-Substrate/minih/issues/26) per Chainglass agent's recommendation; lives in `src/runner/agent-pack/` not in permissions.
- **Migration of existing stale installs**. Operators run `minih agent install <slug>` manually; FX008's hard-fail tells them to.
- **Auto-fixing the resolved policy**. The precondition refuses; it does not silently rewrite the resolved policy to `write: allow` because that would re-introduce the silent-misconfig surface this fix exists to eliminate.
