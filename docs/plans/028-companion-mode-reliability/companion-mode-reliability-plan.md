## Summary

GitHub issue #50 reports that minih's `code-review-companion`, driven by an orchestrating agent, is not reliably drivable: the orchestrator cannot learn a live run's `runId` during its boot/active window, and even successful reviews can be invisible or misclassified. The unifying fault is that run-discovery read-paths **fail closed** (null / empty / misleading error) during a run's active window instead of surfacing a live-pid run as active; plus four independent correctness defects (local-time run IDs labelled `Z`, a child env var pointing at the run dir, findings written to an unreadable lane, clean runs recorded as failed). This plan fixes the live defects A–G with Full TDD and real on-disk fixtures, reusing the injectable liveness/clock seams and the reconcile lock that already exist, so an orchestrator can deterministically learn a live `runId`, identifiers and the child project root are correct, a companion's findings are readable through one documented command, and a clean shutdown is distinguishable from a crash. Scope excludes schema item #5 (fixed in 0.2.1) and the idle-policy *trigger* wiring (follow-up #49) — this plan lands G's terminal *vocabulary and write path*, #49 lands the idle trigger. **Plan v1.1.0 adds Phase 5** (a user-directed scope extension from the #50 follow-up comment): companion *longevity* — a runner-side heartbeat plus configurable idle/stall/timeout ceilings so a companion survives long human-in-the-loop gaps without prematurely timing out, composing with (never pre-empting) #49. The larger "attach + feed commits" alternative is flagged as a follow-up.

**Key risks**: Fail-open must not mask a genuinely stalled run (preserve Plan 025/026 semantics — `updatedAt` freshness still drops a hung run to `stale`/`dead`); C is partly investigative (Finding 05).

## Harness Seams
- **Entry point**: `/eng-harness-flow --event <seam> [--phase <id>] [--plan-dir <p>] --json` — the single door to the engineering harness; child skills are private and never named here.
- **Backpressure** (post-spec seam): not run for this plan (the build path was chosen directly). The testing substrate is already deterministic (injectable `isProcessAlive`/`now`, on-disk fixtures, no schema gate), so coverage is effectively Strong without a Phase 0.
- **Pre-implement** (`--event pre-implement`): fired by the implement verb at the start of each phase (the N.0 rows); verdicts narrated verbatim (`healthy / SLOW / UNHEALTHY / UNAVAILABLE`). `UNAVAILABLE` falls back to standard testing.
- **Phase end** (`--event phase-end`): fired at each phase seam (the N.z rows); `--event plan-complete` fires at merge.
- **Best-effort**: every item is advisory and never blocks; the router decides what the harness does at each seam.
